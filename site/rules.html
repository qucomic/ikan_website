规则如何工作

  1. 搜索或发现：请求列表页，提取作品名、作者和详情地址。
  2. 章节目录：请求详情页或目录地址，提取章节名和章节链接。
  3. 内容解析：请求章节页，取出文字、图片资源或播放地址。

result、lastResult、baseUrl、host、keyword 和 page 在各阶段之间传递数据。

最小小说规则

下面仅展示规则结构。example.com 与选择器均为示例，需要按目标站点修改，不能作为可用来源直接导入。

{
  "id": "example-novel",
  "name": "示例小说源",
  "host": "https://www.example.com",
  "contentType": 1,
  "enableSearch": true,
  "searchUrl": "/search?q=$keyword&page=$page",
  "searchList": ".book-item",
  "searchName": ".title@text",
  "searchResult": "a@href",
  "chapterList": ".chapter-list li",
  "chapterName": "a@text",
  "chapterResult": "a@href",
  "contentItems": "#content@text"
}

contentType: 1 表示小说，0 表示漫画。id 和 name 必须存在。

编写时的注意事项

  • 普通地址模板使用 $keyword / $page；JavaScript 中直接使用 keyword / page。
  • && 合并多个规则结果；|| 按顺序取第一个非空结果。
  • 地址以 @js: 开头时先执行 JavaScript，不会先按 :: 拆分。
  • fetchMode: "webview" 是规则级请求模式，不支持 @webview: 地址前缀。
  • 相对 URL 基于当前页 baseUrl 解析，不必总是手动拼接 host。
  • 加密图片请返回结构化图片对象与 transform；命名处理器定义在 loadJs。
